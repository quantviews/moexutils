# План развития проекта MOEX Utils

## Обзор
Проект фокусируется исключительно на данных Московской биржи (MOEX): получение, хранение и проверка данных акций, облигаций и производных инструментов, расчеты метрик и исследовательские ноутбуки (marimo). Никаких ML-моделей или международных данных — это отдельные проекты.

*Обновлено: 29.09.2026.*

## Состояние на 29.09.2026

**Данные:**
- акции: 100 тикеров, из них 75 торгуются (обновлены по 28.09.2026), 25 сняты с торгов (`metadata/delisted.csv`, история сохраняется);
- индексы IMOEX, MCFTR, RGBITR; ключевая ставка ЦБ по 27.07.2026 (14,00%), обновляется автоматически;

**Код и эксплуатация:** 135 офлайн-тестов, CI на GitHub; все 6 marimo-ноутбуков исполняются на свежих данных; ночное обновление `MOEX data nightly` (вт–сб 00:30, ~30 с) с проверкой качества в конце — первый ночной запуск 29.09 прошел успешно.

## Приоритет 2. Облигации — аналитика

1. **Кривая КБД MOEX:** параметры G-кривой Nelson–Siegel–Svensson по дням (`/iss/engines/stock/zcyc`); G-спреды корпоратов — к официальной кривой, а не к интерполяции по выпускам. Проверить глубину истории, которую отдает ISS.
2. **Терм-спред 10y−2y** во времени — из кривой.
3. **Breakeven-инфляция:** поле `BEICLOSE` для ОФЗ-ИН уже есть в `market_ALL` — ряд инфляционных ожиданий по датам; флоатеры ОФЗ-ПК исключить из построения кривой.
4. **Кредитные спреды:** медианный `ZSPREAD` (уже в данных) и G-спред по срокам, типам и ликвидности как барометр кредитного риска; дефолты — из реестра выпусков (`HASDEFAULT`, `HASTECHNICALDEFAULT`) для статистики по годам.
5. **Денежные потоки выпусков:** графики купонов, амортизаций и оферт (`/iss/statistics/engines/stock/markets/bonds/bondization/<SECID>`) — для точных расчетов доходности и дюрации вместо упрощенной модели `calculate_ytm`.
6. **Строка долгового рынка в `stocks-performance.py`:** RGBITR, сдвиг кривой за период, терм-спред.

## Приоритет 3. Производные инструменты

1. **Реестр контрактов:** по истории — базовый актив, месяц и год из `SHORTNAME`, последняя дата торгов как дата экспирации; учесть повтор кодов раз в 10 лет.
2. **Непрерывные ряды** по основным активам (Si, RTS/RI, BR, GD, MIX, CNY и др.): склейка при ролловере по открытому интересу или за N дней до экспирации, с сохранением исходного контракта в строке (по образцу `source_ticker`).
3. **Базис и implied rate:** Si против USD/RUB (CETS) → рыночная ставка carry, сравнение с ключевой ставкой.
4. **Открытый интерес и объемы** — в обзорный ноутбук.
5. **Опционы — решение отложено.** Около 38 тыс. строк в день сейчас; полная история — сотни тысяч запросов и гигабайты данных. Варианты: все целиком (вне облачной папки), по основным базовым активам и ближайшим экспирациям, или только текущие доски для IV-поверхности.

## Не делаем
Redis, REST API, отдельный веб-дашборд — marimo-ноутбуки закрывают потребность. ML-модели и международные данные — отдельные проекты.

## Принципы
- Модульность и совместимость с существующими данными.
- Каждая новая функция — с офлайн-тестами (ISS мокается) и записью в `docs/`.
- Корпоративные события — только через реестры в `metadata/`, не через правки данных.
- Загрузчики не теряют данные молча: сбой — остановка и докачка в следующем прогоне.
- Файлы пишутся атомарно, один раз за прогон и только при изменениях.
