# Пробная история отдельных контрактов Barchart

Продолжение: [проверка шести экспираций и времени цены](barchart-contract-timing.md).
Все шесть пар совпали по цене исполнения с предыдущей доступной ценой Barchart;
точные исторические редакции спецификаций и время публикации всего ряда не подтверждены.

Статус на 08.10.2026: пользователь получил все шесть ответов через свою сессию
браузера. Данные импортированы, предварительное сравнение с MOEX и Yahoo выполнено.
Прямой HTTPS-запрос к публичной странице
KCZ25/price-history/historical вернул HTTP 403 (CloudFront Request blocked), в том
числе вне сетевой песочницы. Это не доказывает отсутствие данных или подписки
пользователя. Переменные BARCHART_API_KEY и BARCHART_APIKEY не настроены.
Для этой выборки данные получены штатной пользовательской выгрузкой из браузера;
серверная загрузка и ночное обновление Barchart не настроены.

## Минимальная выборка

### Получение через открытую сессию браузера

Пользователь предоставил пример запроса сайта к
`/proxies/timeseries/historical/queryeod.ashx`. Cookies в проект не переносились.
В примере `data=monthlynearest` означает месячный ближайший ряд, а
`volume=total` запрашивает совокупный объём. Такой ответ не подходит как история
отдельной экспирации. Подготовлен [скрипт браузера](../scripts/barchart_browser_pilot.js):
шесть последовательных запросов с `data=daily`, `volume=contract`, без back adjustment.
Полученные ответы содержат ожидаемые символы и дневные даты. Семантика расчётной
цены и полнота архива этим ещё не подтверждены.

1. Открыть Barchart в браузере под своим аккаунтом.
2. DevTools (F12) → Sources → Snippets → New snippet: вставить содержимое скрипта
   и запустить Ctrl+Enter. Скрипт использует сессию браузера, не читая cookies.
3. Сохранить полученный `barchart-pilot-*.json` вне Git, например в
   `F:/moex-data/reference/barchart/`. Это сырой ответ, ещё не принятые данные.

Прокси запрашивается с лимитом 640 дневных записей на контракт, без недоказанного
синтаксиса фильтра дат; фактический диапазон и нужное пересечение проверяются после
получения. При HTTP-ошибке, HTML/XML или сетевом сбое скрипт останавливается и
сохраняет уже полученные ответы с признаком остановки. Повторных попыток нет.
Ответ HTTP 200 сам по себе не подтверждает наличие данных: формат и ошибки внутри
ответа должны быть проверены перед импортом. Заголовки ответа и токены не сохраняются.

Дневная история отдельных контрактов, период запроса 01.08.2025–30.04.2026,
в пределах фактической жизни каждого контракта. Без Nearby, Continuous и
back adjustment. Каждый контракт — отдельный исходный файл.

| Рынок | Две соседние серии Barchart | Валюта и единицы для проверки |
|---|---|---|
| COFFEE | KCH26, KCK26 | Coffee C, ICE US, центы США/фунт |
| ORANGE | OJH26, OJK26 | Orange Juice, ICE US, центы США/фунт |
| TTF | TGH26, TGJ26 | Dutch TTF Gas, ENDEX; проверить EUR/MWh |

Страницы, подтверждающие наименования выбранных серий:
[KCH26](https://www.barchart.com/quotes/KCH26),
[KCK26](https://www.barchart.com/futures/quotes/KCK26/price-history/historical),
[OJH26](https://www.barchart.com/futures/quotes/OJH26/historical-download),
[OJK26](https://www.barchart.com/futures/quotes/OJK26/futures-prices),
[TGH26](https://www.barchart.com/futures/quotes/TGH26/comparison),
[TGJ26](https://www.barchart.com/futures/quotes/TGJ26).
Наличие страницы не подтверждает доступность всей запрошенной истории.

Желательные поля: symbol, trading date, open, high, low, close, settlement,
volume, open interest. Close/Last нельзя молча переименовывать в settlement.
Если расчётная цена недоступна, сравнение закрытий маркируется отдельно.
Сохранить описание единиц, часового пояса/сессии и сроков контракта, если доступно.
Не восстанавливать эти сведения из одного только имени файла.

Счётчик означает NOT NULL, а не ненулевую стоимость. Это покрытие MOEX, не число

## Проверка после получения

1. Сохранить неизменённые исходники вне Git в MOEX_DATA_ROOT/reference/barchart,
   время получения, источник, параметры запроса и SHA-256.
2. Проверить символы, даты, пропуски, дубли, единицы и тип цены. Парсер писать по
   фактическому формату образца; неподтверждённые поля не выдумывать.
3. В futures-analytics сопоставить серии по спецификации и общим датам без
   заполнения пропусков. Отдельно проверить календарь и время фиксации цены.
4. Сравнить ошибку уровня и изменения внутри каждой серии с текущим Yahoo-прокси
   на тех же датах и том же типе цены MOEX; измерить спред соседних экспираций.
5. Дать заключение, улучшает ли архив модель. До этого не менять синтетические
   ряды и не объявлять историю пригодной для бэктеста или расчёта исторической ВМ.

Справка Barchart: [выгрузка истории](https://help.barchart.com/support/solutions/articles/242748-how-can-i-download-historical-data-),
[getHistory API](https://www.barchart.com/ondemand/api/getHistory).
Ключи API и пароли не должны попадать в чат, документы, Git или журналы.

python -m moexutils.barchart_pilot --source F:/moex-data/barchart/barchart-pilot-2026-10-08T13-27-35-124Z.json --output F:/moex-data/reference/barchart/NEW_PACKAGE

Чтение без сети: `from moexutils.barchart_pilot import read_contracts`;
`read_contracts(folder)` проверяет версию пакета и SHA-256 Parquet.

Ошибка уровня — MAPE. Доходности вычисляются до фильтрации пропусков, интервалы
длиннее семи календарных дней исключаются; число пар доходностей меньше числа дат.
Дополнительно сохранены сравнение с CLOSE MOEX, выборка с положительным объёмом
Barchart и спреды соседних зарубежных серий. Ни одна цена не заполняется вперёд.

Вывод: отдельные экспирации полезны для изучения базиса и роллов. В этой выборке
они улучшают уровень цены кофе и сока, но не дают устойчивого улучшения дневных
изменений. Для TTF эффект смешанный. Перед расширением архива необходимо подтвердить
соответствие контрактов, тип close и время фиксации; торговый бэктест и ВМ не рассчитаны.
