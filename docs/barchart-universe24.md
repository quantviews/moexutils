# Соединение зарубежной цепочки universe24

Запрос от futures-analytics принят 15.10.2026. Цель — соединить пакеты
`history-2020-2024-extended-20261014` и `expansion-20261009`, сохранив отдельные
контракты и фиксированный переход 15-го числа месяца перед поставкой.

**Статус: семь серий получены, проверены и объединены 15.10.2026.**
Новый пакет содержит 160 контрактов и 185348 строк. Пересечений символов
между тремя входными пакетами нет; все исходные строки сохранены точно.
Снимок для потребителя остаётся **05.10.2026**. Вся доступная история сохраняется
как исходник; более поздние бары не продлевают бэктест автоматически.

Первые четыре серии закрывают переход **из истории 2020–2024 в 2025 год**;
для уже построенной цепочки, заканчивающейся 31.12.2024, они не требовались.
Так сохраняется прогрев в раннем архиве и дальнейшая непрерывность universe24.
Последние три нужны для позднего зарубежного ряда, но не включаются в вариант
сигнала, использующий после листинга только MOEX, без отдельного решения потребителя.

Границы календарные, не требования к наличию баров в выходные. 15.10.2026 —
текущий день подготовки запроса: полный правый буфер может ещё отсутствовать.
Получение последнего бара само по себе не доказывает, что он завершён. Неполный
буфер и покрытие самого снимка по 05.10 проверяются отдельно; цены не дописываются.

## Получение через браузер

Копия для запуска: `F:/moex-data/barchart/barchart-universe24.js`.
[Версия в репозитории](../scripts/barchart_browser_universe24.js),
[манифест](../scripts/barchart_universe24_manifest.json).

1. Открыть Barchart под своим аккаунтом, F12 → Sources → Snippets.
2. Создать сниппет, вставить текст файла, запустить Ctrl+Enter.
3. Сохранить `barchart-universe24-*.json` в `F:/moex-data/barchart/`.

Семь последовательных запросов, пауза 10 секунд. Режим `data=daily`,
`volume=contract`, `backadjust=false`, `splits=false`, `padded=false`, до 10000
строк на серию. Фильтры дат в неизвестном API не угадываются: запрашивается вся
доступная история, полнота проверяется после получения. Continuous/nearest не используются.
Cookies не читаются и не экспортируются. При HTTP-ошибке, включая 429, сохраняется
частичный результат и запросы прекращаются. Автоповтора нет; продолжение после
устранения причины — с `START_INDEX`, указанного в `stopped.index`.

Raw сохраняет symbol, OHLC, volume и OI, дату, URL и время получения ответа.
Месяц поставки сохраняется в manifest и coverage. `received_at` не является
временем публикации; публикация остаётся `unknown_received_at_is_not_publication`.
CLOSE сохраняет смысл `provider_close_not_verified_settlement`, нулевые объёмы
не удаляются, пропуски не заполняются.

## Импорт и приёмка

```powershell
python -m moexutils.barchart_expansion --source F:/moex-data/barchart/UNIVERSE24.json --manifest scripts/barchart_universe24_manifest.json --output F:/moex-data/reference/barchart/NEW_UNIVERSE24_PACKAGE
```

Несколько продолжений этой кампании можно указать после `--source`. Нужен новый
каталог. Конфликтующие повторные ответы не заменяются автоматически; разные
кампании не смешиваются на стадии сырого импорта.

Приёмка выполнена по следующим правилам:

- Проверить все семь символов, формат, OHLC/объём/OI, дубли, NULL close, лимит строк,
  покрытие нужного участка и десятидневных буферов. Флаги границ требуют разбора
  по сессиям, а не заполнения выходных. Наличие всех ответов не равно полной приёмке.
- Сохранить отдельный пакет с manifest/summary, исходными ответами и SHA-256.
- Явно проверить пересечения символов с обоими исходными пакетами. Совпадающие
  серии требуют сверки версий; `barchart_merge` откажется их тихо объединять.
- Для общего календаря добавить `delivery_month` в новую объединённую копию
  манифеста: старый `expansion-20261009` использует поля соответствия MOEX, а не
  схему исторического манифеста. Исходные манифесты сохраняются без изменений.
- Сверить выбранную ближнюю серию для каждой даты и цены старой/новой серии в
  один день на переходах. Не выбирать дальнюю серию вместо отсутствующей ближней.
- Отдельно оставить даты без баров всех соседних серий. Для ещё не истёкших
  контрактов последняя доступная строка не проверяется как состоявшаяся экспирация.

Если снимок будет продлён после 05.10.2026, сначала пересчитать необходимый набор
месяцев поставки по тому же правилу. Нельзя просто продлить последний доступный
контракт. Аналитический расчёт выполняется только в futures-analytics после
приёмки нового пакета; рыночные данные в том проекте не скачиваются.

Общий справочник: [синтетические фьючерсы](synthetic-futures.md).

## Результат приёмки 15.10.2026

- Новый импорт: `F:/moex-data/reference/barchart/universe24-bridge-20261015`
  (7 контрактов, 7993 строки).
- Объединённый пакет: `F:/moex-data/reference/barchart/universe24-20261015`
  (120 исторических + 33 expansion + 7 новых контрактов).
- Проверка цепочки: `F:/moex-data/reports/barchart-universe24-20261015`.
  `coverage_dates.parquet` содержит выбор серии по датам и статусы;
  `roll_marks.parquet` — цены обоих контрактов на переходах.

Все SHA-256 проверены, дублей symbol/date и NULL close нет. Исходные пакеты
не изменены; вложенные манифесты и ответы сохранены с контрольными суммами.
Месяцы поставки старого expansion восстановлены из символов только в новой
копии метаданных; это не подтверждение исторических дат экспирации.

Проверка 01.01.2020–05.10.2026 по правилу перехода 15-го числа:

| Рынок | Сессии с ценой ближнего контракта | Будние даты без баров соседних серий |
|---|---:|---:|
| COFFEE | 1699 | 65 |
| ORANGE | 1700 | 64 |
| TTF | 1741 | 23 |

Отсутствующих ближних контрактов и баров на наблюдаемых сессиях — 0.
Все 155 переходов имеют обе цены в один день; отсутствующих оценок
удерживаемого контракта — 0. Общие пропуски имеют статус
`no_peer_session_unverified`, а не автоматически признаны праздниками.
Официальный календарь полностью не подтверждён, `full_history_verified=false`.

KCZ26 и OJX26 заканчиваются 14.10.2026: до правой границы буфера 15.10
не хватает одного календарного дня. TGX26 содержит 15.10, но завершённость
этого бара не подтверждена. Для снимка по 05.10 это не мешает покрытию.
Более поздние строки сохранены в raw/Parquet, потребитель обязан применять
`snapshot_end=2026-10-05` из manifest; физически пакет ими не обрезан.
Нулевые объёмы сохранены и не являются подтверждением исполнимости сделки.

Повторение проверки (нужна зависимость `moexutils[reference]` и новый каталог):

```powershell
python -m moexutils.barchart_chain_audit --package F:/moex-data/reference/barchart/universe24-20261015 --output F:/moex-data/reports/NEW_AUDIT --start 2020-01-01 --end 2026-10-05
```

Бэктесты futures-analytics этим импортом не перезапускались.
