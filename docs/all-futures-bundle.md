## Что находится в пакете

| Файл | Содержание |
|---|---|
| `history.parquet` | Все исходные поля FORTS; ключ `date, SECID, BOARDID`; LEFT JOIN реестра и последней карточки |
| `contracts.parquet` | Полный реестр, включая истекшие серии |
| `descriptions.parquet` | Все сохраненные наблюдения карточек, raw_json, источники и время получения |
| `parameters.parquet` | Все наблюдения текущих параметров и ГО; без переноса на прошлые даты |
| `coverage.parquet` | По SECID/BOARDID: границы истории, NULL и нули отдельно, границы заполнения каждого поля |
| `asset_coverage.parquet` | Покрытие по активу и типу инструмента |
| `funding_availability.parquet` | Наличие, период, число свечей и ошибки каждого SECID/FUSR либо SECID/FUSC |
| `funding_comparison.parquet` | Полное соединение свечей и FORTS по дате; исходные значения, разности, статусы и аномалии timestamps |
| `raw/*.json`, `raw/*.parquet` | Все страницы ответов ISS, URL, время получения и нормализованные свечи; имена — SHA-256 от SECID/board |
| `summary.json` | Версия 1, снимок, время, SHA-256 кода/артефактов, статус и ограничения; записывается последним |

В `history` добавляются `asset` (реестр с fallback на исходный ASSETCODE), `registry_asset`,
`registry_present`, `start_date`, `expiration_date`, `source_type`, `instrument_type`.
`perpetual_card_confirmed` требует TYPE=futures и явного признака PERPETUAL_FUTURES
или автопролонгации в наименовании. Дата 2100 не используется как единственное основание.
`collateral_excluded` сохраняется в истории для прозрачности, но не считается бессрочным фьючерсом.

## Чтение и обновление

```python
from moexutils.futures_bundle import read_table

root = r'F:\moex-data\reports\futures-bundles\20261008T105011980359Z'
new_markets = read_table(root, 'history', assets=['COFFEE', 'TTF', 'ORANGE', 'ED', 'UCNY', 'NIKK'])
crypto = read_table(root, 'history', assets=['BTC', 'ETH', 'SOL', 'XRP', 'TRX', 'IBIT', 'ETHA', 'ETHAA'])
coverage = read_table(root, 'asset_coverage')
funding = read_table(root, 'funding_comparison')
parameters = read_table(root, 'parameters')
```

Чтение работает без сети и PostgreSQL, проверяет SHA-256 выбранного файла и принимает
только завершенный пакет версии 1. Фильтр assets поддерживается у `history`, `coverage`,
`asset_coverage`. Прочие таблицы сохраняют исходные идентификаторы и читаются целиком.
Выбор серии и построение непрерывного ряда остаются отдельными действиями потребителя.

```powershell
python -m moexutils.futures_bundle --workers 4
# Без сетевой сверки свечей, только выгрузка снимка:
python -m moexutils.futures_bundle --no-compare
```

Опция `--output PATH` требует нового каталога. Ошибки отдельных загрузок фиксируются;
остальные инструменты продолжают загружаться. Пакет с ошибками имеет статус `partial`,
CLI возвращает код 1, API отказывается читать его как завершенный. Пустой корректный ответ
ISS отмечается `empty_source`, а не превращается в ставки с нулями. Автоматического
возобновления внутри каталога пока нет; следующий запуск создает новый пакет.

Шаг 1e ночного обновления вызывает `export_if_due()`: полный пакет со сверкой создается
через семь дней после последнего успешного, при его отсутствии — сразу. Сбой не откладывает
следующую попытку. Сырая история и наблюдения параметров продолжают обновляться каждую ночь
по основному расписанию. `--no-futures` отключает шаг; `--check` не создает пакет.
CNY сохраняет отдельный ежедневный пакет и мониторинг. Первый автоматический запуск
расширенной выгрузки после подключения еще не подтвержден; ручной прогон успешен.

## Ограничения

FUSR сопоставляется с SWAPRATE, FUSC — с SWAPRATE_CURR. Найдено **1 019 числовых
расхождений**, 5 644 совпадения, 7 NULL FORTS на общих датах; еще 1 099 дат есть только
в свечах и 7 116 — только в истории. Суммы относятся ко всем инструментам и обеим доскам.
Статус `equal_numeric_only` не доказывает одинаковую окончательность или время публикации.
Многодосочная неоднозначность отмечается отдельно; строки не соединяются произвольно.

Данные не заполняются нулями и не заменяются свечами. Лот 1 000 CNY и формула CNYRUBF
не переносятся на другие инструменты. Для криптоиндексов, ETF, валютных и товарных
контрактов требуются собственные единицы, множители и валютный пересчет. Точные исторические
редакции, клиринговый календарь, окончательность фандинга и историческое рублевое ГО
этой выгрузкой не восстанавливаются. Это готовый пакет **исходных данных**, а не подтверждение
готовности всех рынков к расчету ВМ или торговой стратегии.
