## Команда предварительной приёмки

```powershell
python -m moexutils.dividends_acceptance `
  --project F:/Yandex.Disk/FINANCE/dividends `
  --handoff F:/Yandex.Disk/FINANCE/dividends/metadata/dividend_events_handoff.json `
  --output F:/moex-data/reports/NEW_DIVIDENDS_ACCEPTANCE
```

Каталог результата должен быть новым. Команда читает закреплённую передачу,
сверяет ID и SHA-256 manifest, запускает валидатор схем/источников/связей из
dividends. Хеши использованного кода валидатора сохраняются: поздние изменения
соседнего проекта нельзя считать тем же аудитом. Код поставщика исполняется
только из явно указанного локального проекта.

Результат содержит таблицы трёх выпусков, события, покрытие, конфликты,
сверку CSV, источники событий, диагностический public_as_of-срез, примеры
причинности, issues, summary и manifest. Исходные байты документов остаются
в закреплённом пакете dividends; отчёт не заменяет поставку. Оригинальный handoff
и manifest скопированы. Более ранние/поздние события не удаляются из экспорта.

Проверяются:

- идентичность бумаги по тикеру и ISIN, дубли и внешние ключи;
- сохранность всех файлов и доказательств через валидатор поставщика;
- запрет приёмки при `integration_ready=false`, частичном покрытии и нерешённых конфликтах;
- публикация, редакция и историческая доступность первичных событий;
- отсутствующие суммы, даты реестра, база акции и сведения о выплате;
- ссылки отмен/поправок на предыдущие события;
- реальные примеры: событие отсутствует за микросекунду до public_available_at
  и присутствует на границе, по каждому доступному году и тикеру.

Отсутствующий пример не означает нулевой дивиденд. `no_dividend` не требует
вымышленной даты реестра или выплаты. Успех причинного теста не доказывает
полноту истории и правильность извлечения даты из текста сообщения.
Поле `target_acceptance_complete` — результат предварительной проверки,
не автоматическое разрешение полного бэктеста.

Все пять доступных причинных примеров прошли. Структурная проверка пакета
прошла, но приёмка **не пройдена**: `integration_ready=false`, 51 запись issues
(несколько отсутствующих полей могут относиться к одному событию).
По всем трём бумагам покрытие частичное. Для LKOH шесть относящихся к периоду
фактов текущей таблицы не имеют доказательства исторической публикации/редакции.
База акции не установлена у четырёх рекомендаций SBER и шести фактов LKOH.
Нерешённых конфликтов в таблице conflicts именно этих выпусков не обнаружено;
это не снимает объявленную поставщиком необходимость исправить парсер.

Диагностический public_as_of.parquet из этого отчёта не подключён к стратегиям
или DuckLake. Поставщик прямо требует пересборки из-за смешения даты списка
участников собрания с дивидендным реестром и разных периодов распределения.

## Что требуется для окончательной приёмки трёх бумаг

1. Новый закреплённый пакет после исправления парсера, `integration_ready=true`,
   повторная проверка исходных сообщений с исправленными датами/периодами.
2. Отдельная матрица покрытия SBER/GAZP/LKOH за 2023–2026: рекомендации,
   утверждения, решения не платить, изменения/отмены, условия и подтверждения выплат.
   Не требуется ждать завершения остальных 1 407 выпусков. Текущее coverage
   поставщика допускает только partial/not_checked/source_unavailable/no_events_found;
   поэтому полноту нужно согласовать отдельным доказательным отчётом, а не
   подставлять неподдерживаемый статус complete. Аудитор пока консервативно блокирует
   автоматическую приёмку такой неполной схемы.
3. Проверить share_basis_date/базу объявленной суммы и ограничения по фактическим
   выплатам; при неизвестной фактической дате сохранить NULL и ограничение, не
   использовать дату реестра. Явно решить, допускается ли модель денежных потоков
   по опубликованному сроку вместо факта выплаты.
4. В moexutils получить derived last_buy_date/ex_date по закреплённой версии
   календаря и режиму расчётов, отдельно от официальных дат. Нынешний preflight
   намеренно не вычисляет эти даты по непроверенным record_date.
5. Выполнить повторную приёмку, примеры до/после публикаций и поправок,
   выпустить общий manifest цен/метаданных/дивидендов для futures-analytics.

Прежние отчёты и пакеты неизменяемы. Новый аудит всегда публикуется отдельно.
