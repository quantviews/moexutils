# Контракт данных для оценочной ВМ CNY — версия 1

Согласовано 08.10.2026: для `futures-analytics` используется **оценочная** вариационная
маржа. Неподтвержденная точность исторических начислений не блокирует исследование.
moexutils предоставляет данные и признаки качества; учет позиций, ВМ, издержек и
результатов стратегии реализуется в проекте-потребителе.

## Правила оценки

Это согласованные допущения модели, не утверждение исторических правил биржи.

1. Источник фандинга CNYRUBF — исходный `FORTS.SWAPRATE`, руб./CNY. Положительное
   значение означает платеж long в пользу short. Модельный лот — 1 000 CNY;
   его историческая применимость остается допущением. Умножение на лот — один раз.
   `SWAPRATE_CURR` сохраняется для диагностики, не суммируется как второй платеж.
2. NULL — неизвестно; настоящий ноль — нулевой платеж. Нет подстановки из swaprates,
   forward fill или нулей. Если у участвующей в начислении позиции неизвестен фандинг,
   ее итоговая оценка за день неизвестна; отдельно известную переоценку можно сохранить.
   Спорное ненулевое или нулевое значение FORTS используется с признаком расхождения.
3. Дневная переоценка использует `SETTLEPRICE`. При его отсутствии нет замены на CLOSE.
   Цены фактического/модельного исполнения открытия и закрытия задает потребитель;
   наличие дневных цен не доказывает одновременное исполнение обеих ног.
4. Модель имеет одну расчетную отметку на наблюдаемый день FORTS. Открытие **до** нее
   участвует в начислении этого дня; открытие **после** — со следующей отметки.
   Закрытие **до** отметки не участвует в ее начислении; закрытие **после** участвует.
   Событие ровно на отметке требует явного порядка. Для открытия до отметки первая
   переоценка идет от цены сделки; далее — от предыдущей расчетной цены. При закрытии
   учитывается движение от последней учтенной цены до цены закрытия без повторного фандинга.
5. Отсутствующие календарные даты, включая выходные, не создают самостоятельных начислений;
   свечи swaprates на такие даты игнорируются для начислений. Если есть строка FORTS,
   она рассматривается как отдельная наблюдаемая отметка. Это приближение календаря.
   Пропуск ожидаемой строки инструмента не означает нулевой результат: его нужно помечать.
6. Округление модели — Decimal, `ROUND_HALF_UP` до копейки после объединения переоценки
   и фандинга на один контракт за отметку; затем умножение на число контрактов.
   Это конвенция потребителя, не обещание совпадения с агрегацией брокера.
7. Фандинг из архива используется для оценки уже прошедших денежных потоков.
   Момент исторической публикации неизвестен: использовать значение как доступный заранее
   сигнал нельзя без отдельного доказательства времени доступности.
8. Комиссии, проскальзывание, требования ГО и позиции задаются отдельно. Между ногами
   не предполагаются неттинг ГО или брокерские льготы. При неизвестных издержках результат
   обозначается как результат до издержек, а не чистая прибыль.

Для срочного CNY фандинг CNYRUBF не применяется. Множитель, валюты и параметры каждой
срочной серии проверяются отдельно по предоставленным наблюдениям или задаются потребителем
как явные допущения. Автоматического переноса текущих параметров на прошлые даты нет.

## Пакет и API

Создание пакета выполняет moexutils:

```powershell
$env:MOEX_DATA_ROOT = 'F:\moex-data'
$env:MOEX_PG_USER = 'moex_reader'
python -m moexutils.perpetual_audit --compare-swaprates
```

Все таблицы берутся в одной транзакции DuckLake; сверка ISS сохраняется с отдельным
временем получения. Пакет содержит `bundle_schema_version=1`, snapshot, время выгрузки,
хеш кода и SHA-256 файлов Parquet. `summary.json` записывается последним.
Для каждого запуска используйте новый каталог: готовый пакет не редактируется.

Потребитель устанавливает `moexutils` и читает конкретный каталог, без сети и PostgreSQL:

```python
import polars as pl
from moexutils.perpetual_data import read_cny_bundle

bundle = read_cny_bundle(
    r'F:\moex-data\reports\perpetual-audit\20261008T102018823041Z'
)
pair = bundle.pair('CRZ6', board='RFUD', start='2026-09-01', end='2026-10-07')
common = pair.filter(pl.col('both_legs_present'))
parameters = bundle.parameter_observations
cards = bundle.descriptions
policy = bundle.metadata['estimation_policy']
```

Каталог выше — проверенный пакет от 08.10.2026, snapshot 7218: 9 372 строки истории,
67 наблюдений карточек и 35 наблюдений параметров. Пример пары возвращает 27 общих дат.
Выбор `CRZ6` служит примером API, не рекомендацией выбора серии.

API версии 1:

| Объект | Содержание и ключ |
|---|---|
| `bundle.history` | Все исходные поля истории, включая спреды; `SECID, BOARDID, date`; признаки качества добавляются без изменения исходных значений |
| `bundle.pair(secid, board='RFUD', start=None, end=None)` | Обычный срочный CNY и CNYRUBF на явно выбранной доске; полное соединение по `date` |
| `bundle.descriptions` | Все доступные наблюдения карточек этих инструментов, включая истекшие: LOTSIZE, UNIT, FACEUNIT, raw_json, source_url, observed_at |
| `bundle.parameter_observations` | Наблюдения MINSTEP, STEPPRICE, LOTVOLUME, INITIALMARGIN, тарифных полей и происхождения; ключ исходной таблицы, без соединения с прошлой историей |
| `bundle.candidate_gaps` | Кандидаты отсутствующих дат из аудита; не подтвержденный официальный календарь |
| `bundle.metadata` | Снимок, версия, хеши, результаты аудита и `estimation_policy` версии 1 |

В паре исходные поля имеют префиксы `dated_` и `perpetual_`, `date` общий.
`dated_present`, `perpetual_present`, `both_legs_present` различают отсутствующую строку и
NULL внутри существующей строки. Полная выдача включает даты вне жизни второй ноги;
интервал задается явно. Выбор ближайшей экспирации, ролл и нормализация котировок не выполняются.
Календарный спред или инструмент неизвестного типа вместо срочной ноги отклоняется.

Признаки качества истории (в паре также с префиксом ноги):

- `funding_state`: `missing`, `zero`, `observed` для CNYRUBF; `not_applicable` для других.
- `fusr_status`, `fusc_status`: статусы сохраненной сверки, в том числе
  `disputed_no_replacement`, `equal_numeric_only`, `forts_only_date`, `not_checked`.
  Отсутствие свечи не равно расхождению, отсутствие проверки не равно успешной проверке.
- `settle_missing`, `registry_missing`, `volume_missing`, `volume_zero`.
- `historical_parameters_verified=false`, `publication_time_verified=false`:
  неизвестная историческая применимость/доступность не превращается в подтвержденную.

Нулевой объем не удаляет строку. Все наблюдения параметров остаются отдельной таблицей:
`observed_at` не заменяет `effective_from/effective_to`. У истекшей серии могут отсутствовать
наблюдения ГО/шага, даже если доступна карточка. Такие значения не восстанавливаются догадкой.

Чтение проверяет контрольные суммы обязательных файлов и уникальность/непустоту ключей
истории. Отсутствующий заявленный файл сверки вызывает ошибку. Пакет без сетевой сверки
допустим с `not_checked`. Автоматического выбора «последнего» каталога нет.
Старые аудиты без версии пакета требуется пересоздать. В пределах версии 1 сохраняются
имена и смысл добавленных полей; несовместимое изменение требует новой версии схемы.

Подробности источников, размерностей и спорных дат — в [аудите](perpetual-futures.md).
Ночной мониторинг подключен к шагу 1e: новый пакет каждый запуск, полная сверка ISS не реже раза в семь дней при успешных запусках. Расчет ВМ в аналитическом проекте остается задачей потребителя.
