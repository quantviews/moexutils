## Работы

1. Для каждого события проследить путь: raw → receipt/индекс → выбор адаптера →
   извлечённые факты → идентичность выпуска/эпизода → версии → export/public_as_of.
   Проверить родительский пакет, фильтры дат/категорий, checkpoint, сохранение
   ранее найденной истории и изменение parser_version. Использовать имеющиеся raw;
   повторное скачивание не нужно, если документ цел и соответствует хешу.
2. Составить таблицу `old_event_id → new_event_id/action/reason/source`.
   Допустимые исходы: сохранено, исправлено, заменено, обоснованно исключено.
   При новом ID сохранить трассировку; не изображать исправление нашего парсера
   как новую публикацию эмитента или задним числом изменённое сообщение.
3. Проверить рекомендацию, утверждение, реестр участников собрания, дивидендный
   реестр и период распределения раздельно. Не смешивать решение «не распределять
   дополнительно» с отменой уже объявленных промежуточных дивидендов.
4. Исправить причину потери данных и добавить регрессионные проверки на четырёх
   сохранённых сообщениях SBER. Проверить обновление от закреплённого родителя,
   повторную сборку без дублей и сохранение причинного состояния до/после поправок.
5. Пересобрать пакет и повторно проверить три бумаги, включая отсутствие потерь
   уже найденных событий GAZP/LKOH. Сохранить неизвестные поля и ограничения;
   не заполнять пропуски нулями, датой реестра или датой загрузки.

## Результат и приёмка

Передать:

- новый неизменяемый пакет с manifest/summary/schema, SHA-256 и первичными байтами;
- отчёт причины расхождения и таблицу судьбы четырёх SBER-событий;
- целевую матрицу покрытия SBER/GAZP/LKOH по годам и типам событий, источникам,
  необработанным документам, ошибкам и неизвестным полям;
- реальные примеры public_as_of до/после публикаций и исправлений, проверку
  отсутствия будущих сведений на исторических входах;
- результаты тестов и валидатора, версии/хеши кода, подтверждение сохранения старых пакетов.

Увеличение общего числа событий не является критерием приёмки. Каждое из четырёх
исчезновений должно иметь подтверждённый исход; корректное исключение ошибочного
события допустимо, молчаливое исчезновение — нет. Нужны подтверждения рекомендаций,
решений, явных отказов, изменений/отмен и доступных условий/фактов выплат именно
по трём целевым бумагам, а не только общие счётчики всего реестра.

Текущий coverage не поддерживает статус complete. Не менять его на неподдерживаемое
значение ради проверки: приложить отдельное доказательное заключение по целевому
покрытию. moexutils затем согласует машинный критерий приёмки. Общий
`history_complete` может оставаться false для остальных бумаг.

Обновить `metadata/dividend_events_handoff.json`: новый package_id/path,
manifest_sha256, snapshot/период, статус целевой готовности и ссылку на отчёт.
`integration_ready=true` ставить только после проверки исправленного пакета;
если ограничения остаются, перечислить их и не объявлять полную готовность.
Расчётные last_buy_date/ex_date по календарю остаются задачей moexutils после
проверки record_date; подменять ими официальные сведения не требуется.
