# Запрос moexutils: CNY premium options / condor v1

Дата: 15.10.2026. Канал передачи — файл
`moexutils/docs/futures-analytics-options-listing-request.md`.
Поручение пользователя: сначала выполнить только приоритет 1 и вернуть
ответ по историческому листингу. Приоритеты 2–3 оставлены как контекст;
массовую выгрузку по ним до результата первого этапа не начинать.
Сбор и обновление выполняет только moexutils; потребитель читает пакет.

## Приоритет 1 — отличить отсутствие листинга от пропуска данных

Инструменты: asset_code=CNY, exec_type=E, margin_style=P, settle_type=S,
underlying_asset=CNYRUB_TOM. Не подменять американскими опционами на фьючерс CNY.
Диапазон диагностики 03.01.2025–14.10.2026, spot-прогрев с 01.08.2024.

На первых сессиях месяцев январь 2025 — сентябрь 2026 (21 сигнал) в текущей
истории не подтверждены серии с остатком 28–42 календарных дня. Нужна
проверка архивного листинга всех таких экспираций, включая контракты без сделок.
Примеры: 03.01.2025 видны только 6/13/20/48 дней; 03.02.2025 — 3/10/17/45;
03.03.2025 — 3/10/17/45. Подтвердить, действительно ли промежуточных серий
не существовало на эти даты, либо восстановить пропущенные записи.

Для 01.10.2026 / CNYP051126XE (экспирация 05.11.2026) нужны сведения
о наличии на 01.10 дальнего put со страйком ≤11,4961382 и дальнего call
≥13,4051447. В текущих данных доступны только 11,9–13,3. Если крылья
появились позже, указать реальную дату/время листинга, не переносить назад.

Точный помесячный список — локальный файл потребителя
`F:/Yandex.Disk/FINANCE/futures-analytics/outputs/options-coverage-20261015-final/coverage.json`.
Схема желаемого ответа: signal_date, expiry, series_name, secid, option_type,
strike, listed_at, delisted_at, known_at, source_url, checked_at, status/reason.
Различать never_listed / listed_no_trades / history_missing / unknown.
Ключ SECID+series_name, проверка интервала действия короткого кода обязательна.

## Приоритет 2 — денежная механика, если конструкции существовали

Для допущенных серий нужны исторические, а не сегодняшние:

- единицы страйка и премии, lot_size, MINSTEP, STEPPRICE, рублёвый множитель,
  валюта, периоды действия спецификации и первичный источник;
- формула и официальная цена денежного исполнения, дата/время поступлений
  и списаний, сбор за экспирацию (не заменять обычным spot CLOSE);
- биржевые/клиринговые тарифы с датами действия, минимумы/округления;
- исторические требования ГО по длинным/коротким ногам, правила зачёта
  защитных ног, уровни риска. Брокерское ГО и применимость нулевой комиссии
  ВТБ отметить отдельно как требующие подтверждения брокером, если их нет;
- дневной mark всех ног для NAV с признаком происхождения (расчётная,
  теоретическая, сделка); официальный mark не маркировать как исполнимую цену.

## Приоритет 3 — исполнение и общий счёт

Для выбранных после приёмки контрактов/дат запросить доступность исторических
bid/ask с временем и объёмом; если недоступны — явно указать глубину архива
и ограничение. Дневные HIGHBID/LOWOFFER не считать синхронной парой котировок.
Минутные сделки также не заменяют bid/ask, но полезны для оценки совместности
четырёх ног. Сначала проверить доступность, не требовать несуществующих данных.

Согласованные CNYRUB_TOM/CETS, LQDT и RUONIA с прогревом, календарём,
датами публикации ставки и правилами доступности денег после продажи LQDT.
RUONIA используется ex post как контроль, не как известная заранее ставка.
История опциона нужна до экспирации допущенных сделок; даты за текущим
срезом отмечать будущими, не объявлять пропуском.

## Пакет приёмки

README, manifest SHA256, дата/время среза и версии источников, parquet,
coverage/gaps по полям и периодам. По каждому пробелу — можно ли восстановить
или источник не публикует. Подтверждённое отсутствие контракта — полноценный
результат запроса, его не нужно заполнять синтетическими ценами.
В первую очередь достаточно ответа по приоритету 1: при реальном отсутствии
серий полная дорогостоящая выгрузка исполнения для v1 не нужна.
