За пределами [шести контрольных экспираций](barchart-contract-timing.md) соответствие
остаётся гипотезой, которую следует проверить по ценам исполнения и правилам.

## Запуск

Открыть [скрипт](../scripts/barchart_browser_expansion.js), скопировать содержимое
в DevTools → Sources → Snippets на странице https://www.barchart.com под своим аккаунтом,
запустить Ctrl+Enter. Копия для удобства: `F:/moex-data/barchart/barchart-expansion.js`.
Cookies не читаются и не экспортируются. Выполняются последовательные запросы
с паузой две секунды, без автоматических повторов, только к тому же сайту.

Запросы: `data=daily`, `volume=contract`, `backadjust=false`, `maxrecords=10000`.
Повышенный лимит — запрос, а не гарантия глубины: прокси может применить собственное
ограничение. Даты фильтруются после получения, неподтверждённый синтаксис диапазона
прокси не используется. Все исходные строки сохраняются.

Сохранить `barchart-expansion-*.json` в `F:/moex-data/barchart/`.
При HTTP-ошибке или неправильном формате сниппет останавливается, скачивает уже
полученные ответы и выводит `stopped.index`. Для продолжения установить `START_INDEX`
равным этому индексу и сохранить следующий JSON отдельно. Не обходить отказ доступа;
сначала проверить состояние сессии на сайте. Если выполнение вручную прервано до
скачивания файла, несохранённые ответы останутся только в памяти браузера.

## Импорт

```powershell
python -m moexutils.barchart_expansion --source F:/moex-data/barchart/FILE.json --output F:/moex-data/reference/barchart/NEW_PACKAGE
```

После `--source` можно указать несколько файлов продолжения. Каталог назначения
должен быть новым. `--manifest` позволяет явно передать путь манифеста; по умолчанию
используется файл scripts/barchart_expansion_manifest.json в checkout проекта.

Импорт проверяет campaign, символы, дневной режим, восемь столбцов, числовые значения,
дубли дат. Одинаковые повторные ответы не дублируются; разные версии одного контракта
отклоняются, чтобы незаметно не смешивать ревизии. Неполная загрузка сохраняется с
`partial_capture` и CLI-кодом 1. Все ожидаемые ответы означают только завершённую
выборку, **не полноту всей истории и не готовность к исполнению**.

В summary.json по каждому контракту отмечены:

- отсутствие ответа;
- достижение запрошенного лимита или ровно 640 строк как риск скрытого ограничения;
- начало зарубежной выборки позже первой даты MOEX;
- конец более чем за семь дней до экспирации MOEX (порог для проверки, не правило биржи);
- NULL close и нулевые объёмы.

Первый зарубежный день может не совпадать с российским из-за календарей: флаг требует
разбора, а не автоматического заполнения. Внутренние пропуски и совпадение цен исполнения
проверяются следующим этапом после получения реальных ответов. Текущие эвристики
не доказывают полноту; `full_history_verified=false` всегда сохраняется.

Артефакты: неизменённые capture-N.json, manifest.json, contracts.parquet, summary.json
с SHA-256. Parquet читается через `moexutils.barchart_pilot.read_contracts`; статус и
покрытие необходимо проверять в summary.json, особенно для частичных пакетов.
Ночной pipeline, стратегии и синтетическая история v1 не меняются.
