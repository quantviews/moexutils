# История позиционирования universe24 и постоянные версии

Проверено 18.10.2026. Это дневные позиции физических и юридических лиц
из ISS, без внутридневного FUTOI. Расчёты стратегий остаются в futures-analytics.

## Дозагрузка

Все 24 актива из `futures-analytics/configs/universe24.json` перечитаны
за доступный диапазон до 16.10.2026 включительно. Добавлено 70 672 строки;
ранее сохранённые строки не исправлялись и не удалялись. Итог: 91 962 строки,
общий диапазон 01.10.2012–16.10.2026. Начало истории индивидуально для каждого
актива; границы и число строк находятся в `coverage.json` и `coverage.parquet`.
История расширена назад для 21 рынка; TTF, COFFEE и ORANGE начинаются в 2025 году.

Пакет: `F:/moex-data/reports/positioning-universe24-backfill-20261018-v2`.
Первоначальный пакет без этого описания сохранён рядом без суффикса `-v2`.
Исходная версия: `F:/moex-data/versions/openpositions/20261018T144630518189Z-5f87c60a`.

Содержимое пакета:

- `positions.parquet` — выбранные 24 актива, исходные единицы и null сохранены;
- `quality.parquet` — число групп, суммы сторон, разность и признак null по активу/дате;
- `coverage.*`, `summary.json`, `universe24.json` — покрытие, результат и состав выборки;
- `version/` — исходные ответы ISS, снимки, журнал и контрольные суммы;
- `package_script.py`, `manifest.json` — сборщик и SHA-256 каждого файла.

Сверены все 24 нормализованных ответа с итоговым снимком и весь выбранный
снимок с DuckLake; дубликатов ключа нет. У дат с обеими группами суммы длинных
и коротких позиций совпадают. Это проверка внутренней согласованности,
а не доказательство полноты календаря публикаций.

## Ограничения качества

В ответах ISS 576 сочетаний актив/дата содержат только одну группу:
CNY — 4, COPPER — 1, NASD — 9, NIKK — 238, ORANGE — 12, RGBI — 312.
Это воспроизведено текущей полной выдачей источника, а не заполнено загрузчиком.
Пропущенные группы не заменены нулями. Для RGBI 16.09.2022 у юридических лиц
`oichange_long` и `oichange_short` равны null; сами позиции известны.
Даты, на которые источник не вернул вообще ни одной строки, не представлены
в `quality.parquet`; официальный календарь публикаций не подтверждён.

`date` — исходный `tradedate`, не время публикации. Архивная загрузка 18.10.2026
не доказывает доступность значений в 2012–2025 годах. Точное историческое время
публикации и отсутствие прошлых исправлений неизвестны. Две сессии задержки
остаются допущением бэктеста, а не подтверждённой гарантией источника.
Предыдущий аудит: `docs/positioning-availability-20261016.md` в репозитории.

## Постоянный архив

Каждый вызов `openpositions.update()` автоматически создаёт уникальный каталог
`MOEX_DATA_ROOT/versions/openpositions/<UTC-время>-<id>/`. Ночной шаг 1f уже
использует этот загрузчик; дополнительная задача планировщика не нужна.
Архив включает оба рынка при обновлении по умолчанию, включая опционы.

- `run.json`: время начала локального запуска;
- `registry.parquet`: нормализованный справочник активов выбранных рынков;
- `<market>-before.parquet`, `<market>-snapshot.parquet`: полные локальные
  таблицы до и после запуска (первого снимка нет, если таблица ещё не существовала);
- `observation-NNNN/response.json`: фактическое тело ответа ISS;
- `observation.json`: URL, актив, диапазон, `observed_at` в UTC и `published_at=null`;
- `before.parquet`, `after.parquet`: строки проверяемого диапазона;
- `changes.json`: вставки, исправления и удаления с ключом и значениями до/после;
- `applied.json`: подтверждение успешной записи данных и отметки прогресса;
- `result.json`: общий статус, время завершения и ошибки;
- `manifest.json`: SHA-256 файлов завершённого запуска.

Вставка старой даты при дозагрузке — `insert`, а не историческое исправление.
Журнал описывает различия локального состояния и нового ответа, не все изменения
источника между наблюдениями. Файлы ответа и различий сохраняются до изменения
DuckLake. Отсутствие `applied.json` означает отсутствие подтверждения применения;
при аварийном завершении также могут отсутствовать итоговый снимок и manifest.
Частично успешный запуск имеет `complete=false`; перед использованием версии
нужно проверить статус, отметки применения и контрольные суммы.

Эти каталоги не очищаются обслуживанием DuckLake и не перезаписываются.
Это постоянная история локальных наблюдений начиная с 18.10.2026, а не восстановленная
история публикаций. Архив следует включить в копирование `F:/moex-data` на NAS;
автоматическая внешняя резервная копия здесь не настраивается.

`read(as_of=...)` продолжает использовать снимки DuckLake с прежним сроком хранения.
Постоянную версию читают напрямую: `pl.read_parquet(path / 'forts-snapshot.parquet')`.
Ночное перекрытие — семь календарных дней, поэтому исправления более старых дат
обнаруживаются только при явном полном перечитывании с `force=True`.

## Повторная проверка

```python
from moexutils import openpositions
result = openpositions.update(
    start='2012-01-01', end='2026-10-16', force=True,
    assets=['Si', 'Eu'], markets=['forts'], workers=4,
)
print(result['version_path'])
```

Без фильтров обновляются все активы обоих рынков. Начало ограничивается
справочником ISS, конец должен предшествовать текущему дню. Дозагрузка назад
не уменьшает сохранённую отметку свежести. Пакет собирается скриптом
`scripts/package_positioning_backfill.py --version <каталог> --output <новый-каталог>
--universe <universe24.json>`; существующий выходной каталог не перезаписывается.
