# Запрос moexutils: время доступности и ревизии дневных позиций MXI

Передан файлом в moexutils 21.10.2026 по поручению пользователя. Работа в чате автоматически не запускалась. Сначала проверка существующих
артефактов и документации источника; расчёт стратегии остаётся в futures-analytics.
Нужен дневной `forts/openpositions/MXI`, не внутридневной FUTOI и не IMOEX.

Контекст: сигнал против знака чистой позиции физлиц, недельный пересмотр,
лаг данных две торговые сессии плюс задержка исполнения. Тест
15.09.2020–16.10.2026 остаётся условным. Сигнал и параметры не изменять.
Лаги 5/10/20 также проверены, но они не исключают поздние пересмотры истории.

Уже известно: `tradedate` — торговая дата; `published_at=null`.
В архиве MXI за 19/20 октября присутствует 20/21 октября около 00:32 МСК.
В трёх постоянных наблюдениях от 18–21 октября нет update/delete; первый
запуск содержит 4682 исторические вставки. Не повторять это как доказательство
отсутствия исправлений за 2020–2026 годы.

Просим:

1. Найти подтверждённую спецификацию или ответ владельца источника о времени
   первой публикации дневных позиций MXI и возможных исправлениях. Указать
   часовой пояс, торговую дату, вечерние/выходные сессии и изменения режима.
   Если официального ответа локально нет, перечислить точные вопросы для MOEX;
   не подменять время публикации временем клиринга.
2. Проверить все доступные локальные снимки MXI, включая DuckLake и пакет
   аудита 16 октября: существовали ли значения к датам принятия решений?
   Для исторической доступности 2020–2026 дать отдельный вывод по покрытию,
   а не присвоить поздней дозагрузке историческое published_at.
3. По повторным наблюдениям построить таблицу: tradedate, observed_at UTC/MSK,
   applied_at, first_seen_at, last_seen_absent_at (если реально наблюдалось),
   версия/путь/хеш, позиции обеих групп. Отсутствующие границы оставить null.
   Первое локальное наблюдение не считать точной первой публикацией.
4. Сравнить все сохранённые версии MXI по ключу date/asset/is_fiz: insert,
   update, delete; отдельно изменения long/short физлиц и смены знака их
   чистой позиции. Отделить дозагрузку ранних дат от ревизий уже виденных строк.
   Показать фактическое окно повторного чтения и слепую зону старых дат.
5. Если точное время и поздние исправления остаются неизвестны, предложить
   ограниченный режим наблюдений MXI: сохранять ответы, положительные и
   отрицательные наблюдения около предполагаемой публикации, а также
   повторные проверки старых дат вне семидневного окна. Периодичность,
   нагрузку и срок указать явно; массовую историческую дозагрузку вместо
   этого не считать восстановлением point-in-time истории.

Нужен пакет без перезаписи прежних: README с подтверждённым/неизвестным,
таблица доступности, таблица изменений и их влияния на знак, источники,
manifest SHA-256. Отдельно ответить: что подтверждено для будущего применения
лага две торговые сессии и что невозможно доказать для прежнего бэктеста.
