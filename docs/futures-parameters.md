## Матрица источников

| Данные | Источник | Доступная глубина и ограничения |
|---|---|---|
| MINSTEP, STEPPRICE, LOTVOLUME, INITIALMARGIN, LASTTRADEDATE, LASTDELDATE, IMTIME и остальные поля блока securities | [ISS: текущие контракты](https://iss.moex.com/iss/engines/futures/markets/forts/securities.json) | Текущий срез. Накопление собственных наблюдений с первой загрузки. Наличие IMTIME не подтверждает время действия всех полей. INITIALMARGIN не разделяет long/short. |
| mr1/mr2/mr3, lk1/lk2, tradedate, updatetime | [ISS: limits](https://iss.moex.com/iss/rms/engines/futures/objects/limits.json) | Источник сообщает границы 22.05.2018–06.10.2026 при обследовании. Выгрузка через `date=YYYY-MM-DD`, включая выходные; `from/till` игнорируются. Это ограничительные уровни ставок обеспечения и лимиты концентрации по **базовому активу**, не рублевое ГО контракта. |
| ASSETCODE, FRSTTRADE, LSTTRADE, LSTDELDATE, LOTSIZE, UNIT, FACEUNIT, EXECTYPE, DELIVERYTYPE, TYPE, GROUP и прочие поля | [ISS: карточка SiZ6](https://iss.moex.com/iss/securities/SiZ6.json) и аналогичные карточки | Текущее описание, в том числе истекших контрактов. Состав полей зависит от контракта. Получение старого контракта сегодня не восстанавливает историю изменений его спецификации. Полный ответ, включая boards, сохраняется. |
| Историческое рублевое ГО по контракту и клирингу | Не установлен | Не восстанавливается из сегодняшнего INITIALMARGIN или ставок риска; прошлое остается неизвестным. |
| Историческая стоимость шага, расчетные валютные курсы, формулы ВМ и их версии | Не установлен в рамках этой загрузки | STEPPRICE текущего среза нельзя переносить в прошлое. UNIT/FACEUNIT сами по себе не устанавливают валюту стоимости шага или использованный курс. |
| Полный календарь открытых сессий, остановок и возобновлений FORTS | Не установлен | Даты публикации risk limits не являются торговым календарем. |

Семантика ставок описана в [изменениях ISS](https://www.moex.com/n56497).
Архив risk limits может возвращать несколько версий одного актива за дату
(например, 09.06.2023). Все различные `updatetime` сохраняются. Полнота журнала
изменений между клирингами не подтверждена; единицы и аномальные значения
исходных ставок автоматически не исправляются.
`updatetime` хранится в исходном виде; его нельзя автоматически считать временем публикации.

## Хранение

Исходные поля `limits`:

| Поле | Смысл |
|---|---|
| `tradedate` | Дата архивного среза из ответа ISS |
| `assetcode` | Код базового актива, не отдельного контракта |
| `mr1`, `mr2`, `mr3` | Минимальные ограничительные уровни ставок обеспечения; сохраняются без пересчета единиц |
| `lk1`, `lk2` | Лимиты концентрации исходного источника; не величина ГО |
| `title`, `group_title` | Наименование актива и группы |
| `updatetime` | Исходное время обновления записи; возможны несколько версий внутри даты |

Полный перечень полей текущего блока `securities` и примеры карточек —
в [справочнике колонок ISS](iss-columns.md#4).
В текущем блоке сохраняется и `SETTLEPRICE_CLR` — последнее опубликованное
значение расчетной цены. Его временная семантика отличается от произвольной
текущей котировки; наличие поля в сегодняшнем срезе не восстанавливает
значения прошлых клирингов и не заменяет аудит исторического `SETTLEPRICE`.

- `futures_parameter_observations`: все поля блока `securities` плюс `observed_at` (UTC),
  `source_url`, `availability=observed`, неизвестные `effective_from/effective_to` (NULL).
  Ключ: `SECID, BOARDID, observed_at`.
- `futures_description_observations`: `secid`, выбранные исходные поля как строки,
  `raw_json` полного ответа, `observed_at`, `source_url`, `availability`, `identity_status`.
  Ключ: `secid, observed_at`. Код сохраняется точно, включая суффикс года;
  отсутствующие ASSETCODE и даты не выводятся из имени контракта.
  Идентификатор проверяется по `description.SECID` (`description_secid`) или,
  если этого поля нет, по `boards.secid` (`boards_secid`). Пустой ответ сохраняется
  как `availability=unavailable`, `identity_status=unverified`; противоречивые
  идентификаторы вызывают ошибку. Неизвестные поля не заполняются предположениями.
- `futures_risk_limits`: исходные колонки `limits`, `date` из `tradedate`,
  `observed_at`, `source_url`, `availability=observed`.
  Ключ: `date, assetcode, updatetime, observed_at`. Повторные наблюдения сохраняются;
  API чтения выбирает последний полученный ответ на дату, сохраняя все его
  версии по `updatetime`. Полные дубликаты строк сворачиваются; конфликтующие
  строки с одинаковым ключом вызывают ошибку.

`observed` означает получение значения из источника. Для дневных ставок дата
относится к архивному срезу; для текущих параметров историческая применимость неизвестна.
Интервалы действия параметров контрактов пока не строятся. Отдельный реестр
редакций документов описан ниже. Существующие таблицы истории и склеек не меняются.

Исходные JSON: `<MOEX_DATA_ROOT>/raw/futures_params/{current,risk_limits,descriptions}`.
Текущие рыночные ответы сохраняются отдельными файлами по времени получения;
кэш карточек и дневных ставок содержит последнюю загруженную версию каждого запроса.
Предыдущие импортированные наблюдения остаются в таблицах. Подтвержденные пустые даты
архива остаются в JSON-кэше и не превращаются в нулевые ставки.
При резервном копировании включайте `raw` вместе с данными и каталогом.

## Загрузка и чтение

```powershell
$env:MOEX_DATA_ROOT = 'F:\moex-data'
python -m moexutils.futures_params --backfill-risk --all-descriptions --workers 4
```

Первичная загрузка проверяет все календарные даты заявленного архива и карточки
объединения текущей выдачи, реестра и SECID сохраненной истории. Кэш позволяет
возобновить сетевую загрузку; повторная запись того же наблюдения идемпотентна.
Ошибки сети, неполная выдача и несовпадение запрошенной даты завершают запуск ошибкой.

Ночной шаг 1e вызывает `futures_params.update()`: новый текущий срез, карточки
текущих контрактов и ставки риска с догрузкой от последней сохраненной даты,
с повторной проверкой последних семи дней. Старые исправления биржи вне этого
окна автоматически не обнаруживаются. Затем независимо вызывается
`futures_rms.update()` для трех дополнительных архивов с таким же окном
повторной проверки. `--no-futures` отключает этот шаг.

```python
from moexutils import futures_params

current_observations = futures_params.read_observations('SiZ6')
descriptions = futures_params.read_observations('SiZ5_2015', descriptions=True)
daily_limits = futures_params.read_risk_limits('2020-01-01', '2020-12-31', asset='Si')
```

Функции чтения только обращаются к DuckLake, не запускают загрузки.
API параметров «действовали на дату» пока не заявлен: для этого необходимы
подтвержденные периоды действия, а не перенос ближайшего наблюдения вперед или назад.

## Дополнительные архивы RMS

Официальный [перечень объектов RMS](https://iss.moex.com/iss/rms/engines/futures/objects.json)
включает следующие загруженные блоки:

| Таблица | Источник и содержимое |
|---|---|
| `futures_staticparams` | [staticparams](https://iss.moex.com/iss/rms/engines/futures/objects/staticparams.json): статические параметры по активам, включая `negativeprices`, `optionmodel`, времена клиринга и исходные коэффициенты |
| `futures_staticparamskeyterm` | [staticparamskeyterm](https://iss.moex.com/iss/rms/engines/futures/objects/staticparamskeyterm.json): параметры по срокам `t`, исходные `r`, `ir`, `vr`, `vvr` и остальные колонки блока |
| `futures_rclimits` | [rclimits](https://iss.moex.com/iss/rms/engines/futures/objects/rclimits.json): ставки и лимиты по активу и уровню `level`; все категории сохраняются |

Сохраняются все исходные колонки, `date` из `tradedate`, `observed_at`, `source_url`,
`availability=observed`, `row_hash`. Ключ всех трех таблиц —
`date, row_hash, observed_at`. SHA-256 исходной строки различает версии, сроки
и категории без предположений об уникальности ключа источника. Только точные
дубликаты строк одного ответа сворачиваются. Единицы значений не преобразуются.
JSON всех страниц сохраняются в `<MOEX_DATA_ROOT>/raw/futures_rms/<блок>/<дата>.json`;
контроль TOTAL не позволяет сохранить неполную выдачу. Пустые даты кэшируются:
365 из 1 212 проверенных дат каждого архива staticparams и 168 из 555 дат rclimits.
При повторном получении кэш заменяется, прежние наблюдения остаются в DuckLake.

```powershell
python -m moexutils.futures_rms --backfill --workers 4
```

```python
from moexutils import futures_rms

terms = futures_rms.read('staticparamskeyterm', '2023-06-13', '2026-10-06', asset='Si')
```

API возвращает последнее полученное наблюдение на каждую дату со всеми его
строками. Это не состояние, известное участнику торгов в тот исторический момент.
Архивы содержат входные параметры риск-модели, а не рублевое ГО long/short
по каждому контракту и клирингу. Полный исторический расчет ГО не реализован.

`futures_specification_editions`:

|---|---|---|

| RTS | [спецификация индекса РТС](https://www.moex.com/ru/documents/3244) | 11 интервалов из доступного перечня начиная с 19.02.2010 |
| SBRF | [старая спецификация на 1000 акций](https://www.moex.com/ru/documents/3352), [общая спецификация российских акций](https://www.moex.com/ru/documents/4979) | 13 интервалов; архив общего документа представлен не полностью, старый лот нельзя переносить на современные контракты |
| BR | [страница контракта](https://www.moex.com/ru/derivatives/commodity/oil/), [файл спецификации](https://fs.moex.com/files/26811) | Ссылка найдена; даты редакций не установлены, строки с вымышленными датами не создавались |

При проверке 06.10.2026 прямые запросы страниц и файла спецификации BR
возвращали HTTP 403. Оригиналы документов не скачаны и не разобраны. Поэтому
у всех 41 записей `document_downloaded=false`, `contract_applicability_verified=false`,
`evidence_kind=web_index_of_official_page`. Поля `source_valid_from/source_valid_to`
содержат даты из перечня, `reviewed_on` — дату проверки; точность — календарный день.
Открытый конец означает неизвестную дату окончания, а не подтвержденное действие
сегодня. Старые страницы могут по-прежнему называть отмененное семейство «действующим».
Внутри документов возможны исключения для серий, пунктов и вечернего клиринга.

Ключ таблицы: `asset_candidate, source_url, source_valid_from, reviewed_on`.
Остальные поля: два флага проверки, `evidence_kind`, `source_valid_to`, `notes`.
Это исследовательский реестр кандидатов; несколько семейств на одну дату допустимы.
Например, запрос Si на 06.10.2026 возвращает два кандидата, не одну выбранную спецификацию.

```powershell
# Явный импорт проверенного реестра; в ночном задании автоматически не выполняется.
python -m moexutils.specification_editions
```

```python
from moexutils import specification_editions

candidates = specification_editions.read_editions(asset='Si', on='2026-10-06')
```

Для завершения восстановления нужны доступные оригиналы редакций и приложений,
проверка исключений для серий и подтвержденные исторические клиринговые курсы.
Отдельно требуется источник фактического рублевого ГО по сторонам и клирингам.

## Контрольные примеры текущей стоимости изменения котировки

По сохраненному наблюдению от 06.10.2026 21:15:05 МСК (`IMTIME` в источнике
`2026-10-06 07:00:04`) проверена арифметика
`изменение котировки / MINSTEP × STEPPRICE` для одного контракта:

| Контракт | MINSTEP | STEPPRICE, руб. | Изменение котировки | Результат, руб. |
|---|---:|---:|---:|---:|
| SiZ6 | 1 | 1 | +100 | 100 |
| RIZ6 | 10 | 16,98618 | +100 | 169,8618 |
| BRZ6 | 0,01 | 8,49309 | +1 | 849,309 |
| SRZ6 | 1 | 1 | +100 | 100 |

Это контроль единиц при **фиксированной наблюдаемой стоимости шага**, без
клирингового округления. Это не проверка полной формулы исторической ВМ:
для валютно-зависимых контрактов нужны соответствующие курсы, расчетные цены,
действовавшая редакция и правила округления. Текущий STEPPRICE назад не переносится.
