# Бессрочные фьючерсы: аудит CNYRUBF

Проверено 08.10.2026 по запросу `futures-analytics/docs/moexutils-perpetual-request.md`.
Это аудит источников и контроль арифметики платежей; торговая стратегия не реализуется.

## Рабочий режим

08.10.2026 согласован оценочный расчет ВМ: [контракт и API для потребителя](estimated-vm-contract.md). Неопределенности ниже сохраняются, но не блокируют исследования с явными допущениями. Новые выгрузки также содержат карточки, наблюдения параметров, версию пакета и контрольные суммы файлов.

## Воспроизводимость

```powershell
$env:MOEX_DATA_ROOT = 'F:\moex-data'
$env:MOEX_PG_USER = 'moex_reader'
python -m moexutils.perpetual_audit --compare-swaprates
```

Без флага сетевых запросов нет. `--output PATH` задает каталог отчета.
Отчет записывается в `<MOEX_DATA_ROOT>/reports/perpetual-audit/<UTC timestamp>/`;
все чтения DuckLake выполняются в одной транзакции. `summary.json` содержит snapshot,
SHA-256 кода, время, счетчики и ограничения. В ночном шаге 1e пакет создается автоматически после обновления FORTS; полная сверка ISS выполняется, если последней завершенной сверке двух досок не менее семи дней или ее еще нет.
Свечи запрашиваются только для CNYRUBF; хранилище не изменяется.

Артефакты:

- `history.parquet`: исходные строки всех досок с LEFT JOIN реестра и последней карточки;
  отсутствие карточки не удаляет строку. Поля карточки относятся к моменту наблюдения, не ко всей истории.
- `coverage.parquet`: первая/последняя дата, дубли, NULL и нули, границы заполнения каждого поля.
- `candidate_gaps.parquet`: кандидаты пропусков относительно дат, наблюдаемых в FORTS.
- `common_dates.parquet`: все общие даты каждой срочной серии и CNYRUBF, исходные поля обеих ног;
  автоматического выбора ближайшей серии и склейки нет.
- `duplicates.parquet`, `perpetual_candidates.parquet`, `other_perpetual_coverage.parquet`.
- `FUSR-raw.json`, `FUSC-raw.json`: все страницы ответов ISS, URL и время получения;
  `FUSR-comparison.parquet`, `FUSC-comparison.parquet`: полное соединение по дате,
  присутствие строк, оба исходных поля фандинга, разности, статусы и аномалии времени окончания свечи.

Результат ниже: `20261008T092512598505Z`, snapshot **7218**, история по **07.10.2026**.
Новая загрузка может дать другие числа: архив ISS не является неизменяемым снимком.

## Единицы, знак и окончательность

По [странице контракта MOEX](https://www.moex.com/a8141), котировка CNYRUBF — руб./CNY,
лот — 1 000 CNY, шаг цены — 0,001 руб., стоимость шага — 1 руб.
Фандинг публикуется без учета лота: сумма платежа получается одним умножением на 1 000.
Положительный фандинг платит long, отрицательный — short.
Внутридневное значение индикативно. Публикация исторического значения сама по себе
не подтверждает его доступность до клиринга.

[Спецификация с 14.09.2026](https://www.moex.com/files/4nsgdpzf0v0mpzzx1t088tvp5t),
п. 2.1 и приложение 1, подтверждает для CNYRUBF формулу
`Round((РЦт − РЦп) × 1000 − SwapRate × 1000, 2)` для long;
первое начисление использует цену сделки вместо предыдущей РЦ. Для short знак обратный.
Расчет производится в mark-to-market, уплата — в расчетную клиринговую сессию следующего
расчетного дня. Итог округляется математически до копеек.
Это устанавливает правила данной редакции, но не время первоначальной публикации поля ISS.
`SWAPRATE_CURR` не является вторым платежом сверх `SWAPRATE`.

Не установлены: гарантия неизменности исторических полей ISS, точные моменты их публикации,
полная применимость редакций с 2022 года и соответствие свечей выходных расчетным дням.
Для бэктеста без заглядывания вперед использовать время получения как известное наблюдение;
историческую доступность данных до него не утверждать. Перечень редакций есть
[на странице документов](https://www.moex.com/ru/documents/24291).

## Контроль long/short

`illustrative_cashflow` использует Decimal и возвращает переоценку, платеж фандинга и сумму
без округления. Функция проверяет арифметику, не восстанавливает клиентскую ВМ:
цены исполнения, участие в клиринге, применимая редакция и округление задаются отдельно.
NULL, NaN и бесконечность отвергаются. Нулевой фандинг — допустимое отдельное значение.

Условный пример на наблюдаемых РЦ CNYRUBF: открытие после клиринга 02.10.2026 по 12,494,
удержание до клиринга 06.10, закрытие после него по 12,704. Исполнение по этим ценам
является допущением. Начисления за 02.10 нет: позиция открыта после клиринга.

| Начисление | РЦ предыдущая → текущая | Фандинг на единицу | Переоценка long | Фандинг long | Итого long / short |
|---|---|---:|---:|---:|---:|
| 05.10 | 12,494 → 12,757 | 0,00381 | 263,00 ₽ | −3,81 ₽ | 259,19 / −259,19 ₽ |
| 06.10 | 12,757 → 12,704 | 0,00484 | −53,00 ₽ | −4,84 ₽ | −57,84 / 57,84 ₽ |
| Сумма | | | 210,00 ₽ | −8,65 ₽ | **201,35 / −201,35 ₽** |

Отдельных начислений за 03–04.10 здесь не предполагается; это условие примера,
а не вывод из нулевых свечей. Комиссии и проскальзывание не включены.
Контроль с одинаковыми ценами и нулевым фандингом дает ноль для обеих сторон;
при фандинге −0,01 руб./CNY long получает 10 ₽ на контракт, short платит 10 ₽.

Независимая проверка знака и масштаба — официальный
[пример MOEX, страница 17](https://fs.moex.com/f/17840/prezentacija-vyhod-i-fanding-v-vechnyh-fjuchersa.pdf):
для короткой позиции USDRUBF воспроизведены платежи 135,60, −100 и 414,50 ₽;
с учетом −1 ₽ по возникшему срочному контракту итог **449,10 ₽**.
Пример относится к USD и декабрю 2022 года; он не подтверждает исторические параметры CNY.

## Что осталось для точного исторического расчета

1. Подтвердить у MOEX финальность, публикацию и исправления SWAPRATE/SWAPRATE_CURR,
   а также происхождение 34/2 расхождений; свечи не использовать как замену.
2. Получить проверенный календарь расчетных дней с привязкой дополнительных сессий.
3. Проверить предыдущие редакции, изменения параметров и исходные клиринговые данные.
   Историческое рублевое ГО этим аудитом не восстанавливается.
4. После этого проверять реальные сделки open/hold/close и обе ноги спреда с комиссиями
   в проекте-потребителе. Текущий результат пригоден для исследования с указанными ограничениями.


## Ночной контроль

`perpetual_monitor.run()` вызывается на шаге 1e после обновления данных и параметров.
Он создает новый пакет, проверяет контрольные суммы и ключи, свежесть CNYRUBF относительно
последней даты FORTS, пропуски SWAPRATE/SETTLEPRICE и кандидаты отсутствующих дат за
последние 14 календарных дней. Ноль фандинга допустим. Сравниваются два последних
наблюдения MINSTEP, STEPPRICE, LOTVOLUME и INITIALMARGIN по инструменту/доске.
Изменение ГО — информационное замечание, а не доказательство дефекта данных.

Сетевая сверка FUSR/FUSC выполняется через семь дней после последней завершенной сверки
или при ее отсутствии. Между сверками пакет содержит `not_checked`; устаревшие статусы
не копируются в новые снимки. В день сверки недавние расхождения поступают в журнал качества;
полный архив разностей остается в пакете. Неуспешная сверка не сдвигает срок следующей попытки.

Замечания сохраняются в `monitor-issues.parquet` и при включенном шаге 3 объединяются с
обычным отчетом в `quality_log`; новые замечания обрабатывает существующий механизм
уведомлений. Ошибка создания/проверки пакета приводит к ненулевому коду обновления.
`--no-futures` отключает этот шаг, `--check` самостоятельно его не запускает.
Устаревание всего рынка проверяет существующий контроль history; здесь проверяется
отставание конкретного CNYRUBF от уже загруженных данных FORTS.

Ручная проверка 08.10.2026 прошла: обнаружены семь изменений наблюдаемого ГО;
замечаний свежести и пропусков CNYRUBF в выбранном окне нет. Фактический первый ночной
запуск после подключения нужно подтвердить по `logs/update.log`.
