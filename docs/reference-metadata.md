# Версионируемые календари и реестры

Обновление 15.10.2026 после получения двух PDF НКЦ:
`363389bd86bb0a48d7a619e89c9faab17a97442e33e2cc370909a76ef6d62f50`.
В ней сохранены оригиналы редакций от 31.10.2024 и 11.02.2025 и результаты
проверки пунктов о поставке. Остаток — три непроверенных текста и четыре

Модуль `moexutils.reference_metadata` сохраняет проверенные пакеты в
`F:/moex-data/reference/metadata/<version_id>` и таблицах DuckLake `lake.meta_*`.
Первая поставка относится к SBRF/GAZR/LKOH за 2023–05.10.2026,
запросам календарей по годам 2020–2026 и проверке документов 15.10.2026.
Это не полный календарь всех рынков MOEX; ответы за 2020/2021 пустые.

## Версии и сохранность

`version_id` — полный SHA-256 конфигурации, хешей входных manifest, версии формата
и кода сборщика. Изменённый источник или сборщик создаёт новую версию.
Повтор неизменных входов возвращает прежнюю. История хранится обычными строками,
независимо от удаления старых снимков DuckLake при обслуживании.

Внутри выпуска:

- `manifest.json` — SHA-256 всех файлов.
- `summary.json` — область покрытия, входы, количества и схемы таблиц.
- `builder.py` — копия сборщика для аудита.
- `meta_*.parquet` — таблицы для независимого чтения.
- `sources/<package_id>/` — копии manifest и всех перечисленных в нём файлов.

Исходные PDF, DOC/DOCX, Excel, JSON, браузерные выгрузки и старые пакеты не
перемещаются и не изменяются. Файлы семи выбранных пакетов дополнительно копируются
с проверкой SHA-256 до импорта и после копирования. Внешние ссылки из документов
автоматически не скачиваются. Старые `ref_splits`, `ref_renames` и остальные
`ref_*` сохраняют прежний контракт.

Все таблицы и маркер `meta_versions` добавляются одной транзакцией. Ошибка
откатывает весь импорт в DuckLake; файловый выпуск остаётся для повторной публикации.
Повтор той же версии — no-op; другой manifest при том же идентификаторе вызывает
ошибку. Поддерживаемый путь записи — `reference_metadata.publish`, не
`lake.write`/`lake.sync`. Запускать одного импортёра одновременно.
Незаконченные `.building-*` сохраняются для диагностики и не являются выпусками.

## Обновление

`scripts/reference_metadata_sources.json` определяет пакеты, manifest, таблицы и
логические ключи. Для нового выпуска указать новые проверенные пакеты и выполнить
из корня проекта:

```powershell
$env:MOEX_DATA_ROOT = 'F:/moex-data'
python -m scripts.import_reference_metadata --publish
```

Без `--publish` создаётся только файловая версия. Импорт локальный, без сетевого
сбора. В ночной запуск он не включён: новая редакция требует проверки источников
и применимости. Неизвестная достоверность при импорте не повышается.

## Таблицы и ключи

Ключ таблиц данных — `(version_id, record_id)`. `record_id` — SHA-256 значений
логического ключа строки из таблицы ниже. Повтор логического ключа останавливает
сборку. У таблиц данных, кроме `meta_artifacts`, есть `package_id` и
`input_artifact` — происхождение строки внутри `sources`.
У реестра `meta_versions` ключ только `version_id`.

| Таблица | Логический ключ внутри версии | Содержимое |
|---|---|---|
| `meta_versions` | `version_id` | Путь выпуска, хеш manifest, created_at, imported_at, scope, версия формата |
| `meta_artifacts` | package, source_artifact | SHA-256, исходный original_path, относительный archived_path внутри выпуска |
| `meta_calendar_entries` | tradedate, currencyid | Отметки НКЦ/ISS: валюта, currency_market, stock_market, файл/хеш источника, присутствие в Excel |
| `meta_calendar_observations` | url | Запрос календаря, observed_at, артефакт и хеш ответа, включая наблюдения без календарных строк |
| `meta_calendar_rules` | url | Источник правил, дата просмотра, вывод, тип доказательства, ограничение |
| `meta_planned_settlements` | secid | Восстановленные даты торгов/поставки/расчётов, лаг, предполагаемый код, метод, флаги |
| `meta_settlement_trace` | secid, date | Дни, проверенные моделью: is_settlement_day, basis |
| `meta_series_calendar` | secid | 57 контрактов, включая будущие: даты, сверка правила, наблюдения и флаги старого аудита |
| `meta_series_editions` | secid, document_sha256, candidate_from | Кандидатные интервалы редакций для контрактов, параметры, точность границ, ограничения |
| `meta_series_gaps` | secid, missing_field | Пробелы старого аудита и причины; исторический результат, не актуальный автоматически список задач |
| `meta_specification_parameters` | asset, document_sha256 | Лот, шаг/стоимость шага, валюта, строка источника, даты редакции, URL, SHA-256 |
| `meta_moex_decisions` | id | Проверенные новости/решения MOEX: классификация, дата действия, вывод, текст, публикация, наблюдение |
| `meta_ncc_decisions` | document_sha256 | Номер, даты утверждения/действия, классификация, вывод, метод и страницы проверки, URL |
| `meta_ncc_editions` | approved_date | Периоды редакций НКЦ, доступность текста, источник, хеш оригинала при наличии, объём проверки |
| `meta_delivery_editions` | secid | Редакция НКЦ на дату поставки 45 контрактов; не аудит всей жизни контракта |
| `meta_ncc_documents` | source_capture, sha256, url | Наблюдения оригиналов НКЦ: контекст, получение, артефакт, число страниц |
| `meta_moex_documents` | sha256, url, capture | Наблюдения оригиналов MOEX: формат, контекст, получение, артефакт |

Исходные колонки сохранены. Полные схемы с типами: `summary.json → schemas`
или `DESCRIBE lake.meta_...`. Даты из Parquet сохраняют DATE, текстовые даты
из JSON остаются VARCHAR ISO-формата. Массивы/объекты JSON, включая страницы проверки,
сохранены JSON-строками. Полностью пустые колонки — VARCHAR NULL.
Границы интервалов включительны; пустой конец — неизвестный конец,
не доказательство действия правила сегодня.

## Время и ограничения

- effective_from/to, source_start/end_date — действие правила;
  candidate_from/to — кандидатный интервал с оговорками применимости.
- published_at — заявленная публикация, если есть в источнике;
  наличие даты не доказывает историческую доступность версии.
- observed_at, received_at — наблюдение/получение источника;
  created_at, imported_at — сборка выпуска/импорт в хранилище.

Эти времена не подменяют друг друга. Отсутствующая календарная строка не становится
официальным разрешением расчётов; нули и NULL сохранены. Восстановленные даты
отделены от официальных отметок. Модель Т+2/Т+1 принята для бэктеста, но флаги
source_date_verified, actual_execution_verified, historical_known_at_verified
остаются false.

Пять недоступных текстов НКЦ и ограничения веб-проверки сохранены. Редакция
31.01.2024 не вступала в силу и отсутствует в meta_ncc_editions; основание
и оговорки пунктов находятся в `sources/ncc_review/registry.json`.
Исходные summary всех пакетов сохранены: принятие модели не переписывает прежний
строгий аудит.

## Чтение с закреплением версии

Первая версия от 15.10.2026:
`2ca35a13a7f7157cd4e578002488c192826ec95863999dd1b4b54e59b48c24c8`.
Она содержит 16 таблиц данных и meta_versions, 141 исходный файл (около 35 MB),
1 872 календарные отметки, 45 плановых расчётов, 90 строк параметров спецификаций.

```python
from moexutils import lake, reference_metadata

versions = lake.query('SELECT * FROM lake.meta_versions ORDER BY imported_at')
version = '2ca35a13a7f7157cd4e578002488c192826ec95863999dd1b4b54e59b48c24c8'
settlements = reference_metadata.read('meta_planned_settlements', version)
calendar = reference_metadata.read('meta_calendar_entries', version)
```

Неявного выбора «самой новой» версии нет. В futures-analytics закреплять
version_id и manifest_sha256 вместе с бэктестом. При SQL-соединениях ограничивать
обе таблицы одной версией, иначе возникнут дубли разных выпусков.
Проверка файлов: `reference_metadata.verify_package(path)`;
независимое чтение: `polars.read_parquet(path / 'meta_planned_settlements.parquet')`.

Тесты проверяют старую/новую версии, повреждённый источник, выход пути за пакет,
повторную публикацию и полный откат при ошибке.
